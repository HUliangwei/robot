# 03 具身智能闭环流程总结

## 1. 什么是具身智能闭环

具身智能（Embodied
AI）的核心不是单纯训练一个模型，而是让智能体通过身体与环境交互：

``` text
感知 → 理解 → 决策 → 执行 → 环境变化 → 再感知
```

形成持续闭环：

\[ o_t `\rightarrow `{=tex}`\pi`{=tex}(o_t) `\rightarrow `{=tex}a_t
`\rightarrow `{=tex}f(s_t,a_t) `\rightarrow `{=tex}o\_{t+1} \]

其中：

-   (o_t)：当前观测 observation
-   (`\pi`{=tex})：策略模型 policy
-   (a_t)：动作 action
-   (f)：环境动力学
-   (o\_{t+1})：下一时刻观测

# 3. 五个核心模块

## 3.1 感知（Perception）

机器人通过传感器获得环境信息。

输入：

-   摄像头
-   麦克风
-   IMU
-   激光雷达
-   关节编码器

形成：

``` text
observation
```

例如：

``` python
observation = {
    "image": camera_image,
    "state": joint_position
}
```

------------------------------------------------------------------------

## 3.2 策略（Policy）

Policy负责：

根据当前观察决定动作。

数学表示：

\[ a_t=`\pi`{=tex}\_`\theta`{=tex}(o_t) \]

输入：

``` text
observation_t
```

输出：

``` text
action_t
```

例如：

``` text
摄像头看到杯子

↓

模型

↓

机械臂移动到杯子位置
```

常见策略：

-   Behavior Cloning
-   ACT
-   Diffusion Policy
-   VLA

------------------------------------------------------------------------

## 3.3 执行（Action）

动作需要转换为机器人控制量。

例如：

Policy输出：

``` text
机械臂末端目标位置
```

经过控制器：

``` text
目标位置

↓

PID / MPC / 控制器

↓

电机电流

↓

电机运动
```

------------------------------------------------------------------------

## 3.4 环境（Environment）

环境负责产生状态变化：

\[ s\_{t+1}=f(s_t,a_t) \]

环境可能是：

### 仿真环境

-   MuJoCo
-   Gazebo
-   Isaac Sim

### 真实环境

-   机器人本体
-   电机
-   传感器
-   物理世界

------------------------------------------------------------------------

## 3.5 数据闭环（Data Loop）

机器人运行产生新数据：

``` text
observation
action
reward
success/failure
```

保存：

``` text
Dataset

episode
 ├── frame0
 ├── frame1
 ├── frame2
 ...
```

用于：

-   模型训练
-   模型优化
-   失败分析

------------------------------------------------------------------------

# 4. LeRobot在闭环中的位置

LeRobot主要负责：

## 数据

``` text
observation
action
episode
frame
```

## 训练

``` text
Dataset

↓

Policy

↓

checkpoint
```

## 推理接口

``` text
observation

↓

Policy

↓

action
```

LeRobot本身不是物理环境。

它不会计算：

\[ s\_{t+1}=f(s_t,a_t) \]

------------------------------------------------------------------------

# 5. Gymnasium在闭环中的位置

Gymnasium提供统一环境接口：

``` python
obs, info = env.reset()

obs, reward, done, info = env.step(action)
```

作用：

连接：

``` text
Policy

↓

Environment
```

不同环境统一接口：

``` text
MuJoCo
Gazebo
Isaac
Real Robot
```

都可以包装成：

``` python
env
```

------------------------------------------------------------------------

# 6. MuJoCo中的闭环

MuJoCo负责物理计算：

输入：

``` text
state_t
action_t
```

内部：

``` text
动力学计算

碰撞检测

接触计算

积分更新
```

输出：

``` text
state_t+1
```

然后生成：

``` text
observation_t+1
```

------------------------------------------------------------------------

# 7. 模仿学习训练流程

以ACT为例：

## 数据采集

人类示范：

``` text
camera

↓

human action

↓

Dataset
```

得到：

``` text
(observation, action)
```

------------------------------------------------------------------------

## 模型训练

输入：

``` text
observation
```

预测：

``` text
action_prediction
```

比较：

``` text
action_prediction

vs

expert_action
```

计算：

\[ Loss \]

更新：

\[ `\theta`{=tex} \]

------------------------------------------------------------------------

## 部署

训练完成：

``` text
checkpoint

↓

Policy

↓

机器人
```

运行：

``` text
observation

↓

policy

↓

action

↓

environment

↓

next observation
```

------------------------------------------------------------------------

# 8. 仿真到真实（Sim2Real）

开发流程：

``` text
MuJoCo/Gazebo

        ↓

训练和验证Policy

        ↓

真实机器人

        ↓

采集真实数据

        ↓

继续优化模型
```

区别：

仿真：

\[ f\_{sim} \]

真实：

\[ f\_{real} \]

目标：

减少两者差异。

# 10. 一句话总结

具身智能闭环：

> 一个策略模型通过传感器观察环境，根据观察产生动作，环境根据物理规律执行动作并产生新的状态，再将新的观察反馈给策略模型，形成持续循环。

核心关系：

``` text
Observation
      ↓
Policy
      ↓
Action
      ↓
Environment
      ↓
Next Observation
      ↺
```
