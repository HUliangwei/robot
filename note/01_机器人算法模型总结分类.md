# 机器人算法模型总结分类

> 适用场景：具身智能、机器人模仿学习、强化学习、视觉语言动作模型，以及后续“布卡机器人”项目。

## 1. 先区分：算法、模型、策略、环境

- **算法（Algorithm）**：训练或求解的方法，例如行为克隆、强化学习、扩散建模。
- **模型（Model）**：被训练的神经网络或函数，例如 ACT、Diffusion Policy、SmolVLA。
- **策略（Policy）**：根据当前观测输出动作的函数。
- **环境（Environment）**：接收动作并产生下一状态、奖励、结束标志的机器人或仿真器。

机器人控制闭环通常为：

```text
observation_t
    ↓
policy / model
    ↓
action_t
    ↓
environment.step(action_t)
    ↓
observation_t+1, reward, done, success
```

---

## 2. 经典控制与规划算法

这类方法不一定需要神经网络训练。

### 2.1 PID 控制

输入误差，输出控制量：

```text
目标值 - 当前值 → PID → 电机/舵机控制量
```

适用于：

- 电机速度控制
- 舵机角度控制
- 云台稳定
- 温度与电源控制
- 机器人底盘速度闭环

### 2.2 状态反馈与轨迹控制

包括：

- LQR
- MPC
- 逆运动学 IK
- 正运动学 FK
- 轨迹插值
- 阻抗控制
- 力控制

适用于已知动力学、状态维度较低、控制目标明确的任务。

### 2.3 搜索与路径规划

包括：

- A*
- Dijkstra
- RRT / RRT*
- PRM
- DWA
- MoveIt 运动规划

主要解决“从哪里走到哪里”，不直接解决视觉模仿学习。

## 3. 模仿学习策略模型

模仿学习从人类演示或专家轨迹中学习：

```text
observation → action
```

训练数据通常来自：

- 真人遥操作真实机器人
- 键盘、手柄遥操作仿真机器人
- 规划器或控制器生成的专家轨迹

### 3.1 单步行为克隆 Behavior Cloning

输入当前观测，预测当前动作：

```text
observation_t → action_t
```

特点：

- 简单
- 易训练
- 容易产生误差累积
- 不擅长表达多种合理动作

最基本数据要求：

```text
observation
  ├─ image
  └─ state
action
```

### 3.2 ACT：Action Chunking Transformer

ACT 使用 Transformer，根据当前观测预测一段未来动作：

```text
observation_t
    ↓
[action_t, action_t+1, ..., action_t+K-1]
```

主要特点：

- 预测动作块，而不是单个动作
- 动作更连续
- 适合机械臂模仿学习
- 通常比大型 VLA 更适合入门

常见训练数据：

```text
observation.image
observation.state
action 序列
```

可选数据：

```text
task 文本
多相机图像
夹爪状态
```

### 3.3 Diffusion Policy

Diffusion Policy 将动作序列看成需要逐步去噪生成的数据：

```text
随机动作噪声
+ 当前 observation
    ↓ 多轮去噪
未来动作序列
```

主要特点：

- 能表达多种合理动作
- 适合多峰分布
- 动作通常较平滑
- 推理过程比直接回归更复杂

数据需求通常与 ACT 接近：

```text
observation.image
observation.state
action 序列
```

因此，同一套完整轨迹通常可以同时训练 ACT 和 Diffusion Policy。

### 3.4 VQ-BeT 等离散动作模型

把连续动作序列编码成离散动作 token，再使用 Transformer 预测。

特点：

- 适合多模态动作
- 将动作建模转化为类似语言 token 预测
- 需要动作离散化或向量量化模块

---

## 4. VLA：Vision-Language-Action 模型

VLA 同时使用视觉、语言和机器人状态：

```text
图像 + 语言指令 + 机器人状态
                ↓
             动作序列
```

典型输入：

```text
observation.images.*
observation.state
task / language instruction
```

输出：

```text
action chunk
```

适合：

- 多任务机器人
- 根据自然语言切换任务
- 跨场景泛化
- 预训练后微调到新机器人

常见模型方向：

- SmolVLA
- π0 / π0.5 类模型
- GR00T 类模型
- OpenVLA 类模型

VLA 通常比 ACT 更依赖：

- 多任务数据
- 语言标注
- 大规模预训练
- 更大显存和算力

对于只有一个固定任务的数据集，语言字段的信息量通常有限。

## 5. 强化学习模型

强化学习通过环境奖励学习策略：

```text
observation
→ action
→ reward
→ next observation
→ 更新策略
```

### 5.1 在线强化学习

模型不断与环境交互并学习。

常见方法：

- PPO
- SAC
- TD3
- DQN

所需信息：

```text
observation
action
reward
next_observation
done
```

特点：

- 可自主探索
- 需要大量交互
- 在真实机器人上代价较高
- 在仿真器中更常见

### 5.2 离线强化学习

只使用已采集的数据集训练，不在线探索。

常见方法：

- CQL
- IQL
- Decision Transformer

数据要求通常比纯模仿学习更多：

```text
observation
action
reward
next_observation
done
```

失败轨迹和不同质量轨迹对离线强化学习可能很有价值。

---

## 6. 世界模型 World Model

世界模型学习环境变化规律：

```text
observation_t + action_t
            ↓
预测 observation_t+1
```

它不是直接输出机器人动作，而是预测“执行动作后世界会发生什么”。

可用于：

- 预测下一状态
- 在模型内部做规划
- 生成未来图像
- 降低真实环境交互成本
- Model-Based RL

训练数据需要：

```text
observation_t
action_t
observation_t+1
```

视觉世界模型还可能预测未来视频帧。

---

## 7. 奖励模型与成功判定模型

奖励模型学习：

```text
当前状态或轨迹 → 得分 / 成功概率 / 偏好
```

可用于：

- 自动判断任务是否完成
- 从人类偏好学习奖励
- 为强化学习提供奖励
- 对生成轨迹进行排序

训练数据可能需要：

```text
图像
状态
动作
任务文本
成功标签
人工偏好标签
```

---

## 8. 感知模型

感知模型不直接输出动作，而是从传感器中提取信息。

### 8.1 视觉模型

- 图像分类
- 目标检测
- 实例分割
- 深度估计
- 姿态估计
- 光流
- 视觉跟踪

### 8.2 语音与音频模型

- 语音唤醒
- ASR 语音识别
- 声源定位
- 音频事件检测
- TTS 语音合成

### 8.3 状态估计

- Kalman Filter
- EKF / UKF
- 粒子滤波
- SLAM
- 视觉里程计
- 传感器融合

这些模型或算法常作为策略模型的前端。

---

## 9. 不同模型需要不同数据吗

### 9.1 可以共享数据的情况

同一批完整机器人轨迹通常可以同时训练：

- 单步行为克隆
- ACT
- Diffusion Policy
- VQ-BeT
- 部分 VLA 微调

前提是轨迹中包含：

```text
observation
action
timestamp
episode_index
```

ACT 与 Diffusion Policy 的主要区别通常不是原始数据不同，而是：

- 时间窗口截取方式不同
- 模型结构不同
- 损失函数不同
- 动作生成方式不同

### 9.2 必须增加数据字段的情况

| 模型类型 | 额外需要的数据 |
|---|---|
| VLA | 语言指令、多任务标注 |
| 强化学习 | reward、done、next observation |
| 世界模型 | observation_t+1 |
| 奖励模型 | 成功标签或偏好标签 |
| 多相机策略 | 所有部署时会用到的相机视角 |

### 9.3 不能直接共享的情况

即使字段维度相同，下列情况也不能直接混用：

- 动作含义不同
- 机器人结构不同
- 相机视角不同
- 控制频率不同
- 单位不同
- 绝对动作与增量动作不同
- 关节空间与末端空间不同

例如：

```text
数据集A：action = 7个关节目标角度
数据集B：action = 末端位置增量 + 夹爪
```

二者不能直接拼接训练。

## 10. 推荐的数据采集字段

为了让数据可复用于多种算法，建议完整记录：

```text
episode_index
frame_index
timestamp

task

observation.images.*
observation.state
observation.env_state（仿真中可选）

action

next.reward
next.done
next.success
```

还应保存：

- FPS
- 动作单位
- 控制模式
- 相机标定
- 机器人型号
- 场景随机种子
- 任务描述
- 成功判据

## 12. 一句话对照

```text
行为克隆：当前观察 → 当前动作
ACT：当前观察 → 未来动作块
Diffusion Policy：当前观察 + 动作噪声 → 去噪后的动作块
VLA：图像 + 语言 + 状态 → 动作块
强化学习：根据奖励学习动作策略
世界模型：当前观察 + 动作 → 下一观察
奖励模型：状态或轨迹 → 奖励 / 成功程度
```
