# MuJoCo、LeRobot、ROS 2、Gazebo 简介

> 这四个工具处在机器人软件栈的不同层次，不能简单理解成互相替代关系。

## 1. 总体关系

```text
                机器人学习层
        LeRobot / PyTorch / ACT / Diffusion
                       ↓ 输出 action

                机器人系统通信层
                       ROS 2
                       ↓

              仿真与真实硬件接口层
          Gazebo / ros2_control / 驱动程序

              高性能动力学仿真层
                    MuJoCo
```

更准确地说：

- **MuJoCo**：物理仿真引擎
- **LeRobot**：机器人学习软件库与数据体系
- **ROS 2**：机器人软件通信与系统集成框架
- **Gazebo**：面向机器人系统集成的仿真平台

---

# 2. MuJoCo

## 2.1 MuJoCo 是什么

MuJoCo 是一个面向机器人、控制和接触动力学的物理仿真引擎。

它负责计算：

- 刚体运动
- 关节运动
- 碰撞检测
- 接触力
- 摩擦
- 执行器作用
- 传感器数据

典型流程：

```text
读取 MJCF / XML 模型
        ↓
创建 model 和 data
        ↓
写入 action / ctrl
        ↓
mj_step()
        ↓
得到新的 qpos、qvel、sensor data
```

## 2.2 MuJoCo 的主要文件和对象

### MJCF / XML

描述：

- 机器人连杆
- 关节
- 几何体
- 质量和惯量
- 执行器
- 传感器
- 场景

### `MjModel`

保存不经常变化的模型参数：

- 关节定义
- 质量
- 几何体
- 执行器
- 时间步长

### `MjData`

保存每一步变化的运行状态：

- `qpos`：位置和关节坐标
- `qvel`：速度
- `ctrl`：控制输入
- `sensordata`：传感器结果
- `time`：仿真时间

## 2.3 MuJoCo 适合做什么

- 机械臂控制实验
- 强化学习训练
- 模仿学习 rollout
- 接触任务
- 动力学验证
- 自定义轻量仿真环境
- Python 直接控制

## 2.4 MuJoCo 不负责什么

MuJoCo 本身不等于：

- ROS 2
- 数据集系统
- 神经网络训练框架
- 机器人驱动框架
- 完整系统通信中间件

它更像一个高性能“物理世界计算器”。

# 2.5 Gymnasium（机器人环境接口层）

## 2.5.1 Gymnasium 是什么

Gymnasium 是强化学习和机器人学习中常用的**环境接口标准库**。

它本身不是物理引擎，也不是机器人模型。

它负责定义：

- 环境如何初始化
- 如何接收 action
- 如何返回 observation
- 如何返回 reward 和 episode 状态

核心接口：

```python
obs, info = env.reset()

obs, reward, terminated, truncated, info = env.step(action)
```

因此 Gymnasium 更像机器人学习中的“环境适配层”。

---

## 2.5.2 为什么需要 Gymnasium

不同机器人环境实现方式不同：

- MuJoCo
- Isaac Sim
- PyBullet
- Gazebo
- 真实机器人

如果每个环境接口不同，Policy 很难复用。

Gymnasium提供统一形式：

```text
                 Policy

                    |
                    |
                 action

                    ↓

              Gymnasium Env

                    ↓

       -------------------------
       |           |           |
     MuJoCo     Isaac       Real Robot

                    |

             observation

```

Policy 不需要知道下面是哪个仿真器。

---

## 2.5.3 Gymnasium、MuJoCo和LeRobot关系

三者职责不同：

```text
LeRobot Dataset

记录专家轨迹：

observation_t
action_t
observation_t+1


        ↓


Policy训练：

observation → action


        ↓


Gymnasium Environment


        ↓


MuJoCo Physics


        ↓


计算：

s(t+1)=f(s(t),a(t))


        ↓


next observation

```

---

## 2.5.4 Gymnasium中的主要概念

### env

环境对象：

```python
env = gym.make("HalfCheetah-v5")
```

代表整个机器人环境。

---

### reset()

初始化环境：

```python
obs, info = env.reset()
```

得到：

\[
s_0
\]

例如：

- 关节角
- 速度
- 机器人姿态

---

### step(action)

执行动作：

```python
obs, reward, terminated, truncated, info = env.step(action)
```

输入：

\[
a_t
\]

输出：

\[
s_{t+1}
\]


内部流程：

```text
action

 ↓

Gymnasium

 ↓

MuJoCo actuator

 ↓

Physics simulation

 ↓

new state

 ↓

observation

```

---

### action_space

定义动作空间：

```python
print(env.action_space)
```

例如：

```text
Box(-1,1,(6,))
```

表示：

- 连续动作
- 6维控制量

可能对应：

- 电机力矩
- 关节目标
- 速度命令

---

### observation_space

定义观测空间：

```python
print(env.observation_space)
```

表示机器人能观察到的信息范围。

例如：

- joint state
- sensor data
- camera image

---

## 2.5.5 Gymnasium在机器人学习中的位置

完整闭环：

```text
observation_t

       ↓

Policy

       ↓

action_t

       ↓

Gymnasium env.step()

       ↓

MuJoCo / Physics Engine

       ↓

observation_(t+1)

```

因此：

- Policy负责决策
- Gymnasium负责交互接口
- MuJoCo负责物理计算

# 3. LeRobot

## 3.1 LeRobot 是什么

LeRobot 是面向真实机器人和机器人学习的 Python 软件库。

主要功能：

- LeRobotDataset 数据格式
- 数据采集
- 数据可视化
- 数据重放
- 模仿学习训练
- 策略推理
- 评测
- 机器人和环境接口
- 模型上传与下载

## 3.2 LeRobotDataset

典型字段：

```text
observation.images.*
observation.state
action

episode_index
frame_index
timestamp

task

next.reward
next.done
next.success
```

数据通常按 episode 组织，每个 episode 包含连续 frame。

## 3.3 LeRobot 中的策略

常见方向：

- 行为克隆
- ACT
- Diffusion Policy
- VQ-BeT
- VLA
- 强化学习策略

训练的核心关系通常为：

```text
observation → action
```

ACT 和 Diffusion Policy 常预测未来动作块：

```text
observation_t
    ↓
[action_t, ..., action_t+K-1]
```

## 3.4 LeRobot 与 MuJoCo 的关系

LeRobot 不负责物理仿真，MuJoCo 不负责数据集和神经网络训练。

组合方式：

```text
MuJoCo 产生 observation
        ↓
LeRobot policy 输出 action
        ↓
MuJoCo 执行 action
        ↓
产生下一 observation
```

也可以在 MuJoCo 中遥操作并用 LeRobotDataset 保存数据。

# 4. ROS 2

## 4.1 ROS 2 是什么

ROS 2 不是传统意义上的操作系统，而是机器人软件中间件和开发框架。

它解决的是：

- 不同程序之间如何通信
- 传感器数据如何发布
- 控制命令如何传递
- 多个模块如何组合
- 分布式机器人系统如何运行

## 4.2 ROS 2 的核心概念

### Node 节点

一个独立功能模块，例如：

- 摄像头节点
- 麦克风节点
- 目标检测节点
- 策略节点
- 电机控制节点

### Topic 话题

连续发布的数据流，例如：

```text
/camera/image
/joint_states
/cmd_vel
/imu/data
```

### Service 服务

请求—响应式调用，例如：

```text
保存地图
复位机器人
读取配置
```

### Action 动作接口

适合耗时任务，例如：

```text
移动到目标点
执行抓取
导航到房间
```

### TF

管理机器人不同坐标系之间的变换。

## 4.3 ROS 2 在机器人学习中的位置

```text
摄像头 / 传感器
        ↓ ROS 2 topic
Python / LeRobot 策略节点
        ↓ ROS 2 command
控制器 / 驱动 / 电机
```

策略模型可以封装成 ROS 2 Python 节点：

```text
订阅 observation
→ 模型推理
→ 发布 action
```

## 4.4 ROS 2 不负责什么

ROS 2 本身不负责：

- 训练 ACT
- 训练 Diffusion Policy
- 计算物理接触
- 自动生成数据集

它主要负责系统集成和信息流。

# 5. Gazebo

## 5.1 Gazebo 是什么

Gazebo 是面向机器人系统仿真的平台。

它通常与 ROS 2 配合使用，模拟：

- 机器人模型
- 传感器
- 相机
- 激光雷达
- IMU
- 关节控制器
- 环境与障碍物
- ROS 2 通信接口

## 5.2 Gazebo 常用模型格式

- URDF
- Xacro
- SDF
- 网格模型

## 5.3 Gazebo 与 ROS 2 的关系

```text
Gazebo 仿真机器人
        ↓
ros_gz_bridge / 插件
        ↓
ROS 2 topic、service、action
        ↓
控制、感知、导航、策略节点
```

Gazebo 更适合验证完整机器人系统：

- ROS 2 通信是否正确
- 传感器话题是否正确
- TF 是否正确
- ros2_control 是否正确
- 控制节点是否能驱动仿真机器人

## 5.4 Gazebo 与 MuJoCo 的区别

| 对比项 | MuJoCo | Gazebo |
|---|---|---|
| 主要定位 | 动力学与控制仿真 | 完整机器人系统仿真 |
| Python 直接控制 | 很方便 | 通常通过插件或 ROS 2 |
| ROS 2 集成 | 需要额外封装 | 生态成熟 |
| 强化学习效率 | 通常较高 | 通常更重 |
| 传感器与系统集成 | 相对精简 | 更全面 |
| 适合阶段 | 算法训练、控制实验 | 系统联调、ROS 验证 |

二者不是绝对替代关系。

    ↓

# 7. Record、Visualize、Replay、Train、Rollout

## Record

记录遥操作或专家控制产生的数据：

```text
observation_t + action_t
```

## Visualize

查看已经保存的数据：

- 图像
- state
- action
- reward
- done
- success

不执行机器人。

## Replay

把记录过的 action 按原顺序重新发送给环境或机器人。

```text
recorded action[0]
→ action[1]
→ action[2]
```

不需要模型推理。

## Train

训练模型学习：

```text
observation → action
```

## Rollout

模型进入环境闭环运行：

```text
observation
→ policy
→ action
→ environment
→ next observation
```

## Evaluation

多次 rollout 后统计：

- 成功率
- 奖励
- 完成时间
- 失败类型
- 动作平滑度
